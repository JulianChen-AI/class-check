# 最终梳理的报告格式

这是面向用户的成品，不是流程日志。格式复用用户认可的课程梳理：重要事项在前，基本信息居中，资料缺漏随后，证据边界收尾。内容全部来自本次实际读取的记录与附件；不复用示例课程的数值、日期或人名。

## 开头：一句结果摘要

说明已核对哪个群和目录、记录范围及条数、实际发现多少资料未放进目标目录。目录未确认或核对未执行时直说，不填零。时间统一声明源时区。不要用“Skill 已安装”“预检通过”代替这句分析结果。

## 最需要关注的事

按紧迫性/影响分组编号，每组有具体事项标题，而非一长串聊天流水账。

- 作业/交付：文件、范围、截止时间、提交方式；缺少具体时刻或方式时明确指出，给实际附件链接。
- 考试：时间、地点、范围、形式、成绩占比、携带要求及相关停课安排，用两列表格呈现。
- 展示/组队：人数、主题要求、时长、报名方式、排期、最近修订和可选名额。
- 考勤/日常：签到方式、补签规则、重要旧作业状态及查分渠道。

只保留该课程确实有的事项；比赛项目改为报名/提交节点、比赛要求、分工、会议决策、资源及当前卡点。事实附来源日期和消息/附件依据；建议明确为建议，未公布就是未知。过期通知可交代背景，不当成新的近期任务。

## 课程基本信息 / 项目基本信息

课程用“项目｜信息”两列表格：教师、助教、上课地点/时间、答疑、学分、教材等；评分构成及考试覆盖范围可在表后简述，区分教材章和课件序号。

项目用同样的简明表格：目标、组织方/导师、成员职责、赛程、交付物、已有资源；没有证据的字段标未知。不要用行业科普和泛泛行动建议填满报告。

## 哪些文件没有放进目标文件夹？

先报告机器核对总数：群文件消息多少项、内容相同多少、目录缺少多少、版本冲突/无法核验多少。重命名及 (1) 不影响内容判断。

### 缺少的课程/项目资料

表格列：**文件（实际本地链接）｜用途/所属内容｜群发送日期**。说明源附件是否已从 WCE 导出、可以直接打开，但尚未保存到目标目录。不要擅自补拷。

### 另有的非课件附件

行政统计表、名单等单列，简述用途与必要隐私提醒，不重复暴露无关同学信息。现有同内容资料只做覆盖总结，重要更新版单独提示；同名异内容说版本待核对，不称已有。

视频/音频等与文件附件分开说明：是否有记录、可否恢复或阅读、是否仅缩略图，不能凭封面宣称读完内容。

## 收尾：证据、边界和可用文件

说明本机历史不保证覆盖手机全部记录、消息范围/时区、未读正文和缺失媒体；给聊天档案及关键附件的可用本地链接。宿主不能呈现本地链接时提供真实绝对路径，不编造 URL。技术字段、逐条哈希和执行日志可留在验证记录，不要淹没正文。

只有用户明确选择只看截图或明确无法继续数据获取时，标题和开头才改成“局部整理/尚未完成完整群分析”，清楚标注未读取历史、未做查缺；不能把这种降级结果当默认成品。
